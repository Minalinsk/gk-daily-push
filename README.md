# 每日时政 + 公考公告推送

每天两次往企业微信里推消息，**两条是分开的消息，不会混在一起**：
**早上**（07:00）先收到「⏰ 考试日程提醒」，再收到「📰 每日时政」（昨晚要闻）；
**晚上**（19:00）只收到「📰 每日时政」（当天要闻）。山西的公告放在最前面。

跑在 GitHub Actions 上：**零成本、零服务器、零第三方依赖**——只用 Python 标准库，不需要 `pip install`。

- **抓取**：13 个源（7 个公考公告 + 6 个时政，含《求是》官网），覆盖各省省考、事业单位
- **定时**：每天跑**两次** —— 北京时间 07:00、19:00，每次再随机延迟 0~20 分钟（避开整点拥堵）
- **两条独立消息**：
  - 「⏰ 考试日程提醒」——**一天一条，只在早上**推（`state` 里记着发没发过，手动多跑几次也不会重复）
  - 「📰 每日时政」——**早晚各一条**：早上推前一天的、晚上推当天的
- **推送**：企业微信群机器人，markdown 消息
- **去重**：时政推过的链接记进 `state/seen.json`；公告靠考试日历的解析记录去重。两者都提交回仓库，只推新内容（内容没变就不写盘、不提交）
- **保活**：`keepalive.yml` 每月 1 号看一眼，距上次提交超过 20 天才补一个提交，保证仓库 60 天内一定有过提交
- **容错**：任何环节出错都会推一条失败通知（带错误类型 + 日志尾部），不会静默死掉
- **国内站点适配**：自动识别 GBK/gb18030 编码；政府站点证书链有问题时自动降级重试

想自己搭一套？直接看下面的 [部署（5 分钟）](#部署5-分钟)。

## 它做什么

1. 每天**两次**自动启动：北京时间 **07:00** 和 **19:00**（各随机延迟 0~20 分钟）
2. 抓 13 个源的列表页，提取最新文章，按源分两类：**公告源** / **时政源**
3. **公告 → 「⏰ 考试日程提醒」**（独立一条消息）：抓公告正文，抽出报名 / 准考证 / 笔试 / 面试时间，
   写进考试日历（`state/exams.json`，累积着用），然后按公告维度推一张时间表
4. **时政 → 「📰 每日时政」**（另一条消息）：早上那次推**前一天**的要闻，晚上那次推**当天**的要闻
5. 把推过的时政链接和更新后的日历提交回仓库

> **两条消息，各推各的**，互不干扰：
> · 日程提醒**一天只发一条**，固定在早上那次（`PUSH_SCHEDULE`）；晚上那次只更新日历，
>   除非"今天一次都没发出去"（早上整个任务挂了）才补一条。
>   真正的"一天一次"由 `state/seen.json` 里的 `last_schedule` 兜底——手动触发、cron 抖动重跑都不会重复。
> · 时政**早晚各一条**，两次内容不重复（靠去重索引）。

## 考试日程提醒怎么工作

列表页只有标题和链接，**时间信息全在正文里**，所以这块是这么干的：

1. 从公告源里挑出"像招考公告"的（标题含「公告 / 简章 / 招录 / 招聘 / 遴选 / 选调」），
   排掉公示、名单、职位表这类；每轮最多抓 `DETAIL_FETCH = 40` 篇正文，
   解析过的走缓存，所以日常只是把"新公告"补齐；
2. 把正文切成小片段（按 `。；，、` 切），片段里**同时出现事件关键词和日期**才算数；
   万一关键词和日期被句号切开了（`1.网上报名。于2026年8月17日…`），
   再用一次"围着关键词看后面 35 个字"的兜底解析补回来；
3. 落到具体事件上，存进 `state/exams.json`：
   `报名开始 / 报名截止 / 缴费截止 / 准考证开始 / 准考证截止 / 笔试 / 面试 / 公示截止`；
4. 推的时候是**公告维度**——只要一篇公告写明了报名或考试时间，就会出现在提醒里：
   - 🔥 **报名进行中**：`报名开始 ≤ 今天 ≤ 报名截止`，按还剩几天排序
   - ⏳ **最近 3 天**：未来 `REMIND_DAYS = 3` 天内要动的事（报名、准考证、笔试、面试）
   - 📋 **其它已定时间的公告**：剩下的都列在这儿，不会因为"离得远"就不提；
     标题重复的（同一篇被华图、中公同时转）自动去重
5. 消息按字节预算组装（`MSG_BUDGET = 3400`，企微 markdown 上限 4096），
   排不下的折叠成"…另有 N 条"。

正文里的写法非常野，这些都是实测见过的：

```
报名时间为2026年9月10日9:00至9月12日17:00
报名时间：9月15至10月26日                      ← 连"日"字都省了
须于2026年10月14日9:00至10月17日8:30……自行下载打印准考证   ← 时间在前，关键词在后
面试定于2026年6月13日、6月14日进行
面试通知书打印：2026年6月11日-6月14日
2026-10-09 09:00 至 2026-10-15 17:00          ← ISO 写法也认
```

**调参**（都在 `config.py`）：

| 参数 | 默认 | 作用 |
|---|---|---|
| `SCHEDULE_ENABLED` | `True` | 整块功能的开关，嫌吵就关掉 |
| `DETAIL_FETCH` | `40` | 每轮最多抓几篇公告正文（正文页常有 100~250KB，解析过的走缓存） |
| `REMIND_DAYS` | `3` | 「最近 N 天」那块看多远 |
| `REMIND_OTHER_MAX` | `20` | 「其它已定时间的公告」最多列几条 |
| `ONGOING_WINDOW_DAYS` | `30` | 「报名进行中」只列这些天内截止的 |
| `MANUAL_EVENTS` | `[]` | 手动补录机器抓不到的固定日期 |

手动补录的写法（比如国考这种官方站抓不到的）：

```python
MANUAL_EVENTS = [
    ("2026-10-15", "报名开始", "2027年度国家公务员考试"),
    ("2026-11-29", "笔试", "2027年度国家公务员考试"),
]
```

> 一个已知的小局限：公告里写「另行通知」的时间抓不到（也确实没有日期可抓）；
> 另外招聘条件里偶尔出现的孤立日期会被忽略——宁可少记，也不推错的日子。

## 每日时政怎么挑

- 只取**时政源**（`kind = "news"`，共 6 个），公告源的内容不在这条清单里
- 每条会自动挂一个**考点标签**（`topics.py`），扫一眼就知道值不值得点开：
  `- 【新质生产力】我国成功发射秦岭卫星01、02星等9颗卫星`
  - 13 个考点：新质生产力 / 经济高质量发展 / 乡村振兴 / 生态文明 / 民生保障 /
    就业教育 / 法治建设 / 文化建设 / 党的建设 / 基层治理 / 改革开放 / 国际外交 / 安全应急
  - 关键词匹配，命中最多词的那个胜出；一个都没命中就不挂标签（不显示「综合」这种空标签）
  - 想让标签不出现：`config.TOPIC_TAGS = False`
- 看哪一天，按运行时间自动切换（`NEWS_WINDOW_AUTO`）：
  - **07:00 那次 → 前一天**（昨晚的新闻）
  - **19:00 那次 → 当天**（白天的新闻）
  - 想固定成某一天：把 `NEWS_DAY` 设成 `"today"` / `"yesterday"`（也可以用环境变量）
- 优先取 URL 日期正好是目标那天的条目；某个源那天没更新时，
  退而取它最新的 `NEWS_FALLBACK_MAX = 3` 条，免得整个源缺席
- 按源轮转着拿（`MAX_PER_SOURCE = 12`，总共 `MAX_TOTAL = 24`），
  消息里按源归拢；推过的链接记进 `state/seen.json`，只推新的
  （所以晚上那次不会把早上的内容再发一遍，只会发白天新增的）

## 关于公考雷达 / 粉笔 / 华图（实测结论）

这几个我都替你试了一遍，实话实说：

**❌ 公考雷达 —— 抓不了。**
它挂了**阿里云 WAF**，第一次访问返回的是一段混淆过的 JS 挑战页（要求浏览器算出 `acw_sc__v2` cookie 才能进）。纯脚本抓不到，硬要破需要实现 WAF 的加密算法——属于绕过人家的反爬机制，随时会失效，也不建议做。

**✅ 粉笔 —— 能抓，但有讲究。**
- 首页是**服务端渲染**的，能直接拿到招考公告的标题和链接，**这个可用**
- 但它的资讯列表页（`/page/exams-information-list`）是**前端渲染**的，HTML 里啥都没有，**抓不到**
- 所以配置里用的是**粉笔首页**（实测 84 条公告），现在不过滤省份，全国都收

**✅ 华图 —— 能抓，而且全国汇总页是"省考全覆盖"的最优解。**
- 全国版 `www.huatu.com/gwy/zhaokao/` 实测 **276 条**，一页里按省份分段堆了 **37 个省市**的公务员公告（也包含山西）。想要"所有大型的省考"，这一条比挨个爬 30 个省官网靠谱得多——省官网大多 403 或 JS 挑战
- 事业单位频道 `sydw.huatu.com` 实测 283 条，全国事业单位招考都在
- 山西频道 `sx.huatu.com/gwy/` 实测 70 条，按日期倒序，作为兜底
- ⚠️ 两个坑：
  1. 全国页是**按省份分段排版**的，山西排在很后面（6.5 万字符里的第 4 万位），`max` 必须开大（现在设 320），否则只能吃到前面几个省
  2. 页面是 **GBK 编码**，`fetcher.py` 里已经做了自动识别，不用管

**✅ 中公 —— 事业单位频道能抓，公务员频道不能要。**
- `www.offcn.com/sydw/` 实测 229 条，**按日期倒序**（0919 / 0918 / 0917…），天然适合"只推新的"，每天还有一条「全国事业单位招聘公告汇总」
- 但 `www.offcn.com/gwy/`（公务员）149 条里大部分是"2027年X省考公告什么时候出""行测每日一练""上岸血泪教训"这种流量文，**不是公告本身，所以没放进来**

**❌ 国家公务员局 / 人社部 / 中国政府网 —— 抓不了。**
全部返回 1KB 左右的 JS 挑战页或 403。想要一手官方公告，只能上真浏览器（青龙面板 + Playwright）。

**⚠️ 官方 RSS 早就停更了。**
人民网 RSS 停在 2025-06，教育频道甚至停在 2016 年；新华网 RSS 也是几年前的内容。所以本项目是**直接解析网页**，不是读 RSS——这样拿到的才是当天新闻。

**✅ 求是网（《求是》官网）—— 能抓，但没有 RSS。**
- `/rss/*.xml` 全部 404，所以直接抓**首页**：文章链接形如 `https://www.qstheory.cn/20260920/<32位hex>/c.html`，一页 37 条左右，能覆盖最近几天的理论文章
- 好处是**不用抓正文就有标题**（标题就在 `<a>` 里），而且 URL 里就带日期（`/20260920/`），"只取目标那天"的过滤直接生效
- ⚠️ 这是政府站，GitHub Actions 的海外机房可能连不上（和山西省考官网一个毛病）。连不上只记一条日志，不影响其他源——本地跑或放在国内机器上跑最稳

## 注意：GitHub 的机器在国内站点上会被区别对待

这是实跑对比出来的（同一套代码，本地 Windows 和 GitHub Actions 各跑一次）：

| 源 | 本地 | GitHub Actions | 说明 |
|---|---|---|---|
| 华图（全国 / 山西 / 事业单位） | ✅ | ✅ | 最稳，主力靠它 |
| 粉笔首页 | ✅ | ✅ | 稳 |
| 新华网 / 人民网 / 央视网 / 中新网 | ✅ | ✅ | 稳 |
| **山西省人事考试网** | ✅ | ❌ 超时 | 境外 IP 连不上（http/https 都超时），**最权威的那个源在 Actions 上用不了** |
| **中公·全国事业单位** | ✅ | ❌ 403 | 中公对 GitHub 的机房 IP 直接拒绝（`www.offcn.com`、`sx.offcn.com` 都是 403） |

也就是说：**Actions 上实际生效的是 10 个源**，山西官方站和中公这两个只在你本机可用。

好消息是山西的内容基本被覆盖了——华图全国页按省份分段，山西那段照样能翻到；加上华图山西频道和粉笔，省考公告漏不掉。只是少了"官方一手"这一层。

真想要官方一手（山西人事考试网 + 国家公务员局），只有两条路：
1. 在**国内 IP** 上跑一份（飞牛 NAS / 青龙面板都行，配个 cron 就是每天 `python main.py`）；
2. GitHub Actions 里挂代理（要额外服务，成本和维护量都上去了，不划算）。

单源失败不影响其他源，也不会让任务失败——所以这两种情况就是日志里多两行 `抓取失败`，消息照发。

## 部署（5 分钟）

### 1. 建仓库

新建一个仓库，比如 `gk-daily-push`。

公开或私有都行，区别只在 Actions 时长：**公开仓库的 Actions 不计费**；私有仓库每月有 2000 分钟免费额度，而本项目单次最长约 21 分钟（0~20 分钟随机延迟 + 约 1 分钟实际抓取，延迟那段时间也算时长），一个月满打满算约 650 分钟，额度够用。

### 2. 传文件

**目录结构不能变**：

```
gk-daily-push/
├─ main.py
├─ config.py
├─ fetcher.py
├─ push.py
├─ state.py
├─ log_utils.py
├─ .gitignore
└─ .github/
   └─ workflows/
      └─ daily.yml      ← 必须在 .github/workflows/ 下，放根目录不生效
```

⚠️ 如果仓库首页能直接看到 `daily.yml`，就是传错了位置。

### 3. 配 Secrets

仓库 → **Settings** → **Secrets and variables** → **Actions**

**Secrets**（New repository secret）：

| Name | Value |
|---|---|
| `WEWORK_WEBHOOK` | 企业微信群机器人 Webhook 地址 |

（跟 wxread 那套一样，直接复制过来）

**Variables**（可选）：`WEWORK_MSG_TYPE` = `markdown`

> 仓库是**公开**的话，Webhook 必须放在 Secrets（加密）里，别放 Variables——Variables 是明文。

### 4. 启用并测试

仓库 → **Actions** → 左侧 `gk-daily-push` → **Run workflow**，两个勾选项：

| 勾选 | 作用 |
|---|---|
| `test_push` | **只发一条测试消息**（不抓取、不动索引）—— 刚配完 Webhook 时用它验证通道 |
| `dry_run` | 真抓取、真解析，但**不推送**，结果只写进 Actions 日志 —— 用来预览内容（本地更推荐 `simulate.py`，见下面的「本地预览」） |

**首次运行只建索引、不推内容**，你会收到一条「已就绪」的提示——避免第一次被几百条历史链接刷屏。
想测试时就看到完整效果：把 `config.py` 里 `FIRST_RUN_PUSH` 改成 `True`，测完改回来。

## 怎么改

### 加一个源

```python
{
    "name": "显示名",
    "url": "列表页地址",
    "pattern": r"文章链接的正则",
    "max": 8,
},
```

`pattern` 怎么写：打开列表页 → 点开一篇文章 → 看 URL 规律。

例：`https://www.news.cn/politics/20260920/e6f43.../c.html`
→ 正则 `news\.cn/politics/\d{8}/\w+/c\.html`

**一条源还支持这几个可选字段：**

| 字段 | 作用 |
|---|---|
| `title_pattern` | 标题不在 `<a>` 里时（比如粉笔），用它从链接后面 500 字里捞标题 |
| `include` | 本源专用白名单，标题不含这些词就不推 |
| `exclude` | 本源专用黑名单 |
| `max` | 本源最多解析几条。**宁可开大**——真正压量的是 `max_age_days` 和去重索引；开小了，分栏排版的页面（比如华图全国页）只能吃到最前面一两栏 |
| `max_age_days` | 覆盖全局的日期限制（公告类内容稀疏，可以放宽到几十上百天） |

### 过滤备考噪声（`STUDY_NOISE`）

培训机构（华图 / 中公 / 粉笔）的页面里混着大量备考类"内容农场"文章。`config.py` 顶上有一组黑名单，公告类源统一套用：

```python
STUDY_NOISE = ["估分", "考情", "考点", "真题", "解析", "答案", "题库", "模拟题",
               "每日一练", "练习题", "网课", "课程", "直播", "备考", "预测",
               "大纲", "冷知识", "血泪", "考什么", "几月份", "什么时候",
               "题型", "经验分享", "上岸经验"]
```

标题里带这些词的一律丢掉。想放宽就删词，想更严就继续加。
**注意别放「图书」「教材」这类词**——"公开招聘图书管理员公告"会被误杀。

### 源的顺序会影响截断

推送时按源轮转挑选，而消息有 4096 字节日志上限，超了会从**尾巴**截断。
所以 `SOURCES` 里把最不该漏的放前面（现在是公告类在前、时政类在后）。

### 换成本省源

各省人事考试网一般长这样：`rst.<省>.gov.cn/rsks/`，里面再分「公务员」「事业单位」栏目。

**最省事的办法**：搜「省份 + 人事考试网」，打开「公务员」和「事业单位」栏目，把两个地址发我，我帮你写好 `pattern`。

### 只推考公相关内容

```python
INCLUDE_KEYWORDS = ["公务员", "招录", "选调", "事业单位", "考试", "公告", "面试"]
```

留空 `[]` 就是不筛。注意这是**全局**规则，会连同（时政源一起筛）。只想筛某一个源，用那个源的 `include`。

### 改推送时间

改 `.github/workflows/daily.yml` 的 cron，**写的是 UTC 时间**（北京减 8 小时）：

| 北京时间 | cron |
|---|---|
| 06:00 | `0 22 * * *` |
| 07:00（默认，带日程提醒） | `0 23 * * *` |
| 19:00（默认，只推要闻） | `0 11 * * *` |

> 想只留一次、或者改成别的时间，直接改 `schedule:` 那两行就行；
> 晚间那条 cron 会让 `PUSH_SCHEDULE` 自动变成 0（workflow 里按 cron 字符串判断），
> 也就是"晚上不重发日程提醒"。就算判断错了，`last_schedule` 那道闸也会挡住重复。

### 改条数 / 日期范围

```python
MAX_TOTAL = 24        # 一条消息最多几条
MAX_PER_SOURCE = 12   # 每个源最多贡献几条
MAX_AGE_DAYS = 3      # 默认只留最近 3 天（公告类源各自放宽）
```

## 几个设计细节（为什么会这样）

**1. 按源轮转挑选，不是从头顺着拿。**
时政源条数多，顺着拿会把公考公告全挤掉——而公告恰恰最不该漏。所以是「每个源先各拿 1 条，再各拿第 2 条」这样分配。

**2. 去重靠索引文件，不是靠时间。**
推送过的链接存进 `state/seen.json` 并提交回仓库，下次只推没见过的。所以同一篇旧文章最多烦你一次。

**3. 只在内容真的变了时才提交；保活交给一个低频 workflow。**
`state.py` 写盘前会先比一次指纹：只有时间戳变了、内容没变就跳过写盘，所以没有新内容的日子**不会**产生提交（安静下来就不会有一堆没意义的提交）。
但仓库 **60 天无提交**会被 GitHub 禁用定时任务（这是它唯一的机制，静默生效、被禁后没法自救），所以另有一个 `keepalive.yml`：**每月 1 号**看一眼，距上次提交超过 20 天才补一个提交——一个月最多一次，平时它什么都不做。

**4. 消息长度双保险。**
企业微信 markdown 上限 4096 字节，组装时按字节数边加边算，超了就截断并记日志，不会发出去被拒。

**5. 首次运行记的是"全部候选"，不是要推的那几条。**
公告类源一页就有两三百条候选。如果只把准备推的 24 条记进索引，剩下的会在之后十来天里被当成"新内容"陆续推出来，等于给你补一星期旧闻。所以 `main.py` 里首次运行走的是 `eligible_by_source()`，把候选池整个记进索引。

**6. 干跑（`dry_run`）不写索引。**
预览时不推送、也**不把内容标记成已推送**，否则"看一下效果"就会悄悄把当天的新内容吃掉，下次真跑反而什么都没了。日程日历照常保存（那部分是无副作用的累积数据）。

**7. 日程提醒"一天一条"是记账记出来的，不是靠 cron 时间猜的。**
发出去了才往 `state/seen.json` 写 `last_schedule = 今天`；下一轮（不管是晚上那次、还是手动重跑）一看今天已发过就直接跳过。这样：
- 早上那次正常发完 → 晚上那次、手动触发都不会再发；
- 早上那次整个任务挂了（没发成、也没记上账）→ 晚上那次会补一条，不至于当天完全没有提醒；
- 发送失败不记账，所以失败还能重试，不会"以为发过了"。

## 出问题了怎么查

**Actions 里没有 `gk-daily-push`** → `daily.yml` 位置错了。

**收到「运行失败」推送** → 消息里带了错误类型、信息和日志尾部。
最常见的两种：`没配 WEWORK_WEBHOOK`（Secrets 没配或名字打错）、`所有源都没抓到内容`（网络或站点改版）。

**某个源条数总是 0** → 去 Actions 日志看「源【XX】没解析出条目」，说明站点改版了，需要更新它的 `pattern`。
单源挂掉不影响其他源，也不会让任务失败。

**企业微信收不到** → 手动 Run workflow 测一次；还不行就检查 Webhook 是否复制完整（末尾 `key=xxx` 不能少）。

**好几天没收到推送，Actions 里连新运行都没有** → 先看定时任务是不是被 GitHub 禁用了（仓库 60 天没提交就会这样）：Actions 左侧点 `gk-daily-push`，顶部有黄色提示就是它，点 **Enable workflow** 即可。也可以手动 Run 一次 `keepalive`。
